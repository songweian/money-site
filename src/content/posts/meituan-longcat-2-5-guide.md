2026 年 11 月 2 日，美团新闻中心刊出 LongCat-2.5。稿件来源写的是经济观察报，技术博客页面标注的日期是 2026 年 11 月 1 日。这是一款面向长程智能体任务的原生多模态模型：总参数 1.6 万亿，技术博客写每个 token 大约激活 480 亿参数。它接在今年 6 月的 LongCat-2.0 后面，加强了原生视觉理解和智能体编程。

对中小团队，这件事值得看的不是参数规模，而是三件已经能核对的事实：训练被新闻稿写成全程使用国产算力；网页和 API 现在就能试，接口同时走 OpenAI 格式和 Anthropic 格式；定价页给出了限时单价，输入每百万 tokens ¥2。下面按官网原文把能做的步骤写出来。模型分工的总原则仍是 [按任务分工，不要整站换新](/posts/october-ai-model-roles/)。

## 发布说明里已经写明的能力

新闻稿的定性是：原生多模态，面向长程智能体任务，总参数 1.6 万亿，训练全程由国产算力完成。今年 6 月发布的 LongCat-2.0，被写成首次在国产算力上完成万亿参数模型的全流程训练与推理。开放平台更新日志把「LongCat-2.0 发布 & 计费」标在 2026-06-30。LongCat-2.5 在这一代上继续加强原生视觉理解与智能体编程，并优化国产算力上的长上下文训练与推理效率。

技术博客把能力写得更具体。视觉信号被表示成多层离散 token，骨干网络用统一的 token 形式处理图像和文字。原生视觉理解和智能体编程放在一起，覆盖看图编程、创意设计和 3D 任务。工程侧增加了长程轨迹，并用大规模长程强化学习加强端到端能力，点名的场景包括复杂代码库开发和完整项目构建。真实智能体跑失败的轨迹，被转成可以复现、可以验证的训练任务，用来补短板。

更新日志对 2026-11-02 这一版的三条说明是：视觉编程、创意设计与 3D；复杂代码库与完整项目上的多步推理、工具调用和端到端执行；兼容 Claude Code、Codex、Hermes 等智能体脚手架。

新闻稿还写了一则经营分析演示：模型自行做渠道利润表，指出支付 GMV 增长 23.2%、渠道利润下降 1.7%，再按清货价值、复购和库存给出配置建议。这是美团技术博客里的案例，经新闻稿转述，用来说明他们想覆盖的商家分析流程。这组百分比只属于该演示案例。同一篇稿写，基于 LongCat 系列的经营工作台「妙手」已经服务古茗、徐升记、益禾堂等品牌。这里写的是系列模型，稿件没有把「妙手」的线上版本逐项标成 LongCat-2.5。商家后台和公开 API 是两个入口。

美团 CEO 王兴在 2026 年 8 月 28 日二季度财报电话会上的话，也被这篇新闻稿引了出来：AI 能力的长期价值，是能否进入真实工作流、解决真实问题，并形成长期稳定的基础设施；模型和 AI 产品用于支持主业，提升用户、商户体验和公司经营效率。这是公司路线，不是接口参数。

## 为什么现在就要看它

第一是价格已经能算。定价页对 LongCat-2.5 按量付费标的是初上线限时价，每百万 tokens：未命中缓存的输入 ¥2（0.30 美元），命中缓存的输入 ¥0.04（0.006 美元），输出 ¥8（1.20 美元）。页面同时写明，实际费用以结算为准。缓存输入正好是未命中输入的五十分之一，因为 2÷0.04＝50，0.30÷0.006＝50。输出是未命中输入的 4 倍。长回答比多塞一段提示更贵。怎么把这类单价放进周预算，可以对照 [GPT-6.1 Terra 的算法](/posts/gpt-6-1-terra-cost-guide/)：先算一笔自己的用量，再决定哪一段工作值得换。

第二是协议。中文快速开始写，平台兼容 OpenAI 的对话补全和 Anthropic 的消息接口。模型名一栏是 `LongCat-2.5`，两种格式都能用。同一把 API Key 可以打 `/openai/` 和 `/anthropic/`。更新日志写它兼容 Claude Code、Codex、Hermes。已经在这些工具里工作的人，试跑时改的是基地址和模型名，密钥放在环境变量里，配置字段以各工具自己的当前文档为准。仓库里的审查习惯继续留着，见 [团队里的 AI 编程助手](/posts/ai-coding-assistant-team-guide/)。

第三是算力路线。新闻稿写训练全程由国产算力完成。技术博客写，长上下文训练和 W4A4 推理按国产 AI 加速器做了优化，单卡显存不到 80GB。中训练阶段使用最长 1M token 的序列，新闻稿写累计训练量达数万亿 token。这和 API 的 1M 上下文是两件事：前者是训练序列，后者是你一次请求能带的总量。采购或合规若要求供应商走国产栈，这一条值得记进评估表。训练发生在国产算力上，并不自动等于你的提示词满足某一条数据出境条款。账户协议里若没有写保存地点、保存多久、会不会用于训练，客户材料仍留在现有环境。额度、训练用途和供应商要分开问，这一点和 [挑免费额度](/posts/free-ai-tool-limits/) 是同一张表。

推理侧可以当作「他们怎样把 1.6 万亿参数的混合专家模型压到 4 比特」来读，当作你自己的延迟承诺来用还不成立。博客写：专家权重和激活都量化到 4 比特，在已评测的下游任务上与量化前相当。线上压测相对权重和激活都是 8 比特的 W8A8 INT8 基线，预填充吞吐提高 43.3%，逐 token 生成吞吐提高 42.77%，首 token 时间缩短 15.91%，后续每个 token 的时间缩短 19.72%。新闻稿把这几项收成约四成、约 16%、约 20%。长上下文监督微调上，优化后的单卡吞吐比 DDP 基线高 86%。这些都是美团自己的测试。

## 基准表：先看表注，再看名次

## 用限时价把四种用量算完

定价页只有三行价，没有按「思考 token」单列。思考过程若计入输出，就落在每百万 ¥8 这一档，以用量明细为准。失败请求不计费：常见问题写明 HTTP 401、403、429、500 不扣余额，只有 HTTP 200 按实际 token 计费。大陆用户充值或购买 Token 资源包之前，要先完成个人实名或企业认证。余额小于等于 0 时，新请求会被拒绝。企业认证之后另有按月累计消费的阶梯折扣。同一份常见问题里，大陆站从月累计 ¥500 的 9 折到 ¥40,000 的 6 折；国际站从月累计 75 美元的 9 折到 6,000 美元的 6 折。定价页没有写这套折扣是否叠在限时价上。下面的例子只乘限时价，不把 6 折再乘进去。

| 用量 | 人民币算式 | 结果 | 美元算式 | 结果 |
| --- | --- | --- | --- | --- |
| 20 万输入未命中 + 5 万输出 | 0.2×2 + 0.05×8 | ¥0.80 | 0.2×0.30 + 0.05×1.20 | $0.12 |
| 2 万未命中 + 18 万命中 + 5 万输出 | 0.02×2 + 0.18×0.04 + 0.05×8 | ¥0.4472 | 0.02×0.30 + 0.18×0.006 + 0.05×1.20 | $0.06708 |
| 命中缓存的那一档重复 20 次 | 20×0.4472 | ¥8.944 | 20×0.06708 | $1.3416 |
| 未命中的贵回合重复 20 次 | 20×0.80 | ¥16 | 20×0.12 | $2.40 |
| 100 万未命中输入 + 100 万输出 | 1×2 + 1×8 | ¥10 | 0.30 + 1.20 | $1.50 |
| 只把输出打到快速开始写的 128K | 0.128×8 | ¥1.024 | 0.128×1.20 | $0.1536 |

128K 那一行只算输出，不含输入，用来看单次回答的封顶，不是建议你每次都打满。一个办公日如果是 20 次上表那种中等回合，全部未命中缓存时是 ¥16；按表中的命中比例则是 ¥8.944。一次把 100 万输入和 100 万输出都用满，是 ¥10。长程编程贵在输出和重复读仓库；缓存命中把输入几乎打到原来的五十分之一，输出单价不动。试跑时打开用量明细，看命中比例，比盯着「每百万 ¥2」这一个数字有用。

## 这周可以做的试跑

网页和 API 分开。网页用来判断「一句话任务它怎么答」，API 用来判断「接到现有工具之后，账和质量是否站得住」。两边都只用去掉客户姓名、未公开报价、账号和密钥的副本。

网页：打开 longcat.ai，用一段你自己写过的短说明，外加一张不含人脸、证件和票据的示意图。看两件事：它有没有把图里的文字或结构写进回答；回答里有没有凭空补上图里不存在的数字。新闻稿写的看图做网页、3D 展示，用一张你有权使用的线框或海报试，成品当草稿。

API 按快速开始的顺序：

1. 注册并登录开放平台。大陆手机号收不到验证码时，常见问题写的客服电话是 1010-7888。大陆用户在充值前完成个人实名或企业认证。先充一笔你愿意试错的小额。按限时价，¥20 等于 25 次「20 万未命中输入 + 5 万输出」，或 2 次「100 万输入 + 100 万输出」。三份样本若走长程智能体，输出按每百万 ¥8 累加，以账单为准。
2. 在 API Keys 页创建密钥。文档写密钥只在创建时显示一次，丢失就要新建。不要把密钥写进仓库、截图或提示词。
3. 模型名填 `LongCat-2.5`。快速开始里的 OpenAI 示例地址是 `https://api.longcat.chat/openai/v1/chat/completions`，Anthropic 示例是 `https://api.longcat.chat/anthropic/v1/messages`。常见问题里又出现过 `/openai/native/chat/completions`。先用快速开始的示例发一句「你好」，确认 HTTP 200，再改基地址去接 Claude Code、Codex 或你现有的 SDK。
4. `max_tokens` 先设 1024。打通之后再加到你的任务需要的长度。快速开始和常见问题写最大输出 128K；模型参数页写 `max_tokens` 上限 262,144。两页不一致，以你这次请求的实际返回为准。越界时参数页写明会返回 400，错误类型是 `invalid_request_error`。
5. 需要流式输出时，请求体里设 `stream` 为 true。限流时返回 429，文档建议客户端做指数退避。

密钥、基地址、模型名，这三样齐了再谈质量。缺任何一样，先不要比较它和现有模型谁更聪明。

## 用三份上周的材料做对照

对照样本从上周真实做过的工作里抽，一天内能由人判断对错。每份同时交给现在的主力模型和 LongCat-2.5，输入保持同一份。

1. 一份看图或设计稿。一张你有权使用的界面草图、海报或简单三维示意。成功标准写成一句：生成的页面或说明是否包含图中的指定元素，有没有多出来的数字。
2. 一份多文件的小改动。一个你确实想改的模块，限制在你看得完的范围内。成功标准：改动能否直接留下，人要返工几分钟。编程助手的合并规则不变，人仍然看 diff。
3. 一份绝不能直接对外的任务。报价、工期、退款、合同。两个模型都只出草稿。这一份用来确认新基地址没有被接到自动发送上。

记录表固定六列：日期、任务、模型名、人是否采纳、返工分钟、这次账单上的金额。一周结束只留一个变化：看图任务或代码任务，哪一边采纳更高并且返工没有变长，就把那一类的试跑范围留在 LongCat-2.5；另一类回到原来的模型。两个一起换，就分不清差别来自哪里。省下的分钟和返工的分钟要放在一起看，算法见 [AI 提效怎么量](/posts/ai-productivity-measurement/)。

思考开关也要记在表上。博客的分数是思考开启时取得的。你若为了省输出 token 关掉思考，那是另一种用法，不要拿去和博客的名次对照。关掉之后如果返工变多，把省下的 ¥8/百万 和返工时间放在同一行，再决定开关。

## 接入前写进备忘的五条

基准是美团自报。新闻稿的「介于 Opus 4.8 与 Opus 5 之间，部分超过 Opus 5」和博客的表，都还没有独立复测。表内已经有 NL2Repo 这种低于 Opus 4.8 的行。对外介绍时引用原句，并补上「美团公布、未见独立复测」。

价格会变。页面标题就是「折扣价 / 百万 Tokens（限时）」，正文写实际费用以结算为准。本文的算式只对 2026 年 11 月 2 日这版定价页负责。改预算或写进报价单之前，重新打开 [定价页](https://longcat.ai/platform/docs/zh/pricing/longcat-2.5)。

### 限时价怎么估算一次调用要花多少钱？

每 100 万 tokens：未命中输入 ¥2（0.30 美元），命中输入 ¥0.04（0.006 美元），输出 ¥8（1.20 美元）。20 万未命中输入加 5 万输出＝¥0.80（0.12 美元）。18 万输入命中缓存时，同一回合是 ¥0.4472。页面写明限时优惠，以结算为准。企业阶梯折扣是否叠加，定价页没有写。

### 上下文是 1M，单次输出是 128K 还是 256K？
