2026 年 11 月 24 日，Anthropic 在 Claude 帮助中心的更新说明里写上了 Install as app 测试：在 Claude 的 Mac 和 Windows 桌面应用里，你可以把一个常用的 Artifact 装成独立应用。它会有自己的图标和窗口，不再只开在 Claude 里。官方介绍页的说法是「从今天开始」逐步推送，面向所有套餐的测试版。9to5Mac 在当天 11:56（太平洋时间，上海时间 11 月 25 日 03:56）报道了这件事；The Verge 的报道时间是 2026-11-24 23:04 UTC（上海时间 11 月 25 日 07:04）；ITmedia 在 11 月 25 日 10:07（日本时间，上海时间 09:07）也做了说明。

这不是新的模型名字，而是把已经在用的小工具，放到和其他软件一样的打开方式里。会议准备页、待发货订单追踪、菜单栏提醒，以前要先打开 Claude，再找到那个 Artifact。现在可以装到电脑上，用已有的 Claude 账号和连接器，不必再打包、签名，也不必另申请 API 密钥。请求仍计入你的套餐用量，而且应用要得到你的允许，才能进一步操作这台电脑。

对中小团队、运营同事和独立开发者，值得写的不是「终于能一句话做软件」，而是两件更具体的事：哪些 Artifact 现在真的能装，以及「完全访问电脑」这档权限该不该开。下面只采用官方介绍页、帮助中心、更新说明，以及 The Verge、9to5Mac、ITmedia 已经写明的范围。Claude 里的文档、幻灯片和表格怎么用，仍看 [Claude Meetings、Sheets 和 Whiteboards](/posts/claude-meetings-sheets-whiteboards-guide/)。套餐用量怎么估，看 [免费 AI 工具怎么挑](/posts/free-ai-tool-limits/)。

## 11 月 24 日发布了什么

综合官方介绍页、帮助中心和 11 月 24 日的更新说明，已经能核对的范围如下：

- **产品形态**：把 Claude 做好的 Artifact 安装为 Mac 或 Windows 应用。装好后有自己的图标，在独立窗口里打开，也可以分享给别人。它还是同一个 Artifact：你或其他编辑者改了内容，应用会跟着更新。
- **可用范围**：测试版，在 Free、Pro、Max、Ultra、Team 和 Enterprise 上逐步推送。只支持 Claude for Mac 或 Claude for Windows，版本需要 6.28899.0 或更高。Linux、网页和手机不可用。打开应用时必须在线，并已登录 Claude。
- **套餐开关**：Team 默认打开，但「完全访问电脑」这档权限默认关闭，要管理员再开。Enterprise 默认关闭，需要所有者在 Organization settings > Artifacts 里打开。官方介绍页还写，Team 和 Enterprise 的管理员可以在组织里开关应用权限和完全访问。
- **不能用的环境**：已做 HIPAA 就绪配置的组织，以及混合部署，不能使用。帮助中心还写：为 Claude Code 开了零数据保留的组织，要等所有者打开 Artifacts 和 Install as app 之后才能安装，而且这些应用不被零数据保留覆盖。Claude for Teachers 和 K-12 组织不能使用完全访问，安装功能也可能关闭或不可用。
- **计费**：官方没有为这项功能单列新价格或新的用量数字。介绍页和帮助中心都写，做应用，以及应用向 Claude 发出的请求，计入当前套餐的用量。

The Verge 的报道和官方材料一致：安装后的应用可以沿用类似浏览器里的默认权限，也可以被授予通知、快捷键、置顶窗口，或完全访问电脑。9to5Mac 和 ITmedia 同样转述了官方「从今天开始」的测试推送，以及不需要打包、签名或另备 API 密钥这一点。这些是交叉核对，不增加官方没写的能力。

## 装上去之后能做什么，不能做什么

官方介绍页举的使用方式，是把日常工具从「分享出去的成品」变成「天天打开的软件」。他们提到的例子包括：定期从日历和邮件里取信息的会议准备页，以及当天待发货订单的追踪工具。帮助中心给的起步描述也偏向这类小工具，例如菜单栏里的番茄钟、每小时提醒你活动一下的小应用，或按日期重命名某个文件夹里照片的 Windows 应用。

装好之后，应用可以使用 Claude，也可以使用你已经接好的连接器，方式和原先的 Artifact 相同。若你允许，它还可以发通知，或在 macOS 菜单栏、Windows 托盘里放一个图标。带菜单栏或托盘图标的应用，关掉窗口后仍会继续运行。要退出时，macOS 可从程序坞退出，或在它是当前应用时按 Cmd+Q；Windows 则在托盘图标菜单里选 Exit。

打开位置也写得很具体：

- macOS：在用户主目录下的 Applications 里，打开 Claude Apps 文件夹；也可以用 Spotlight 或 Apps 启动器。若要留在程序坞，按官方说明对该图标选 Options > Keep in Dock。
- Windows：从开始菜单的 Claude Apps 文件夹打开，或使用桌面上的快捷方式。
- 也可以在 Claude 桌面应用里，对这个 Artifact 选 Open installed app，或到 File > Apps 里打开。Windows 上 File 在菜单按钮（☰）下面。

有几件事现在做不到，需要提前划清，避免试点做到一半才发现走不通：

- 用模板做出来的 Artifact，例如 Docs、Slides、Sheets，不能安装。旧格式的 Artifact，以及 Claude Cowork 的即时 Artifact，也不能安装。
- 浏览器里的「添加到程序坞」「添加浏览器快捷方式」「添加到主屏幕」只是快捷方式，并不具备这里说的桌面能力。
- 在 macOS 上，若 Claude 正在使用电脑，它能看见已安装的应用，但不能在里面点击或输入。
- 卸载应用不会删除原来的 Artifact。若 Artifact 被删除、下架，或不再分享给你，打开应用时 Claude 通常会建议你卸载。

官方介绍页还展示了 Anthropic 内部用过的几个应用，例如分层图像编辑器 Linnet、文件管理器 Phosphor、按规则整理文件夹的 Sift、带 Claude 协助的终端 Tern，以及查看电脑运行状况的菜单栏或托盘应用 Vitals。这些是官方点名的内部例子，不是单独售卖的正式产品，也不等于你用同一句提示词就能得到同样的结果。

## 三种权限分别意味着什么

对要把这类应用真正用到工作里的人，权限比「能不能装」更要紧。官方把权限分成三档，而且应用在用到这些能力之前必须先询问，你每次回答 Allow 或 Don't allow。

| 权限档位 | 官方写明的范围 | 更适合先试的工作 | 先不要拿它做的事 |
| --- | --- | --- | --- |
| 默认 | 只能做浏览器里也能做的事 | 查看、计算、在窗口里展示已经允许的内容 | 还没看清来源，就让它改文件或跑程序 |
| 应用权限 | 通知、全局快捷键、置顶窗口并读取鼠标位置、菜单栏或托盘图标 | 提醒、计时、在角落里看一眼状态 | 把来源不明的应用设成开机后一直在托盘里跑 |
| 完全访问这台电脑 | 运行程序，并不再逐次询问地读取、修改或删除文件；除非你或组织关掉了上一档，否则也包括上面那些能力 | 只给自己做的、并且已经在受控目录里试过的整理类工具 | 给组织外的人做的应用，或来源无法确认的应用 |

有几条边界必须按原文理解，不能自行放宽：

- 一次 Allow 只覆盖当前这个版本。应用更新后，包括你自己改过的版本，Claude 会再次询问。Don't allow 会一直保持，直到你改口。
- 如果应用从其他网站加载了代码，那部分代码可以在不重新询问的情况下变化。这是官方写明的风险，不是边角注释。
- 完全访问只能给自己做的应用；在 Team 和 Enterprise 上，也可以给本组织成员做的应用。免费和各类个人付费套餐里，「组织外」指的是你以外的任何用户。
- 若应用来自组织外部，或 Claude 无法确认是谁做的，请求时会显示警告。官方还写：如果应用有一部分是组织外的人写的，或无法确认作者，通常不允许它申请完全访问。
- Anthropic 明确说，安装前不会审查这些应用。只把完全访问给自己信任的人写的东西。

若要改权限或收回权限：macOS 在应用打开时，点菜单栏里的应用名，再选 Permissions；Windows 是在标题栏右键，或按 Alt+Space，再选 Permissions；也可以在 Claude 桌面应用的 File > Apps 里选中应用后打开 Permissions。官方提醒：关掉完全访问可能导致应用重新加载或关闭，先保存再改。它会停下该应用启动的程序，但已经从应用里分离出去的程序除外，而且不会撤销应用已经做过的修改。

若你失去了对某个应用的访问，例如分享者停止分享，它启动的程序也会停。官方写，这通常最多大约 20 分钟；若 Claude 当时无法检查，例如离线、已退出登录，或正在使用另一个组织，等待时间可能更长。同一菜单里如果有 Report Artifact，可以用来举报应用。卸载入口在 File > Apps，选中后选 Uninstall。macOS 上应用会进入废纸篓，Windows 上会去掉快捷方式；若你还把它留在程序坞、任务栏或开始菜单，需要自己再摘掉。卸载会去掉你给过的权限，但不会删除 Artifact。

这类「装上去就能碰文件」的能力，和之前讨论过的扩展、依赖来源是同一类问题。不要把来源不清的应用直接开到完全访问，必要时可对照 [提示词注入防护清单](/posts/prompt-injection-defense-checklist/)，以及我们写过的 [Claude Code 扩展后门排查](/posts/claude-code-extension-backdoor-check/)。

## 为什么这对用 AI 干活的人重要

过去两年，很多人已经习惯让 Claude 做出一个页面、一份跟踪表，或一个计算器，然后把链接发给同事，或自己在 Claude 里反复打开。Install as app 要解决的，是官方说的那句话：如果你真的靠一个工具做事，它就应该像其他应用一样打开，并在需要你处理时提醒你。

对职场人和小团队，这意味着三件很实际的变化。

第一，常用小工具可以离开聊天窗口。会议前要看的日程摘要、每天要核的发货清单、盯着用的用量提醒，不必每次先找到那次对话。这会缩短「打开工具」的步骤，但不会自动让工具更准。应用仍然要在线，仍然要用你的 Claude 账号，请求也仍然走套餐用量。

第二，分享方式更接近装软件，而不只是发一个网页链接。官方介绍页写，装好的应用可以分享给别人，对方也可以安装。对小团队来说，这比「大家都收藏同一个 Artifact 链接」更方便，也更容易把权限问题带进办公室：你允许自己的应用发通知，不等于同事安装后也该给它完全访问。

第三，权限模型把「能做网页上的事」和「能改这台电脑」分开了。这是它和普通聊天附件最大的差别。默认档并不危险到不能试；真正要谨慎的是完全访问，以及应用从其他网站加载代码、更新后不必再问的那一段。把一个还没看过的应用直接开到最高权限，风险不在功能名好不好听，而在文件和程序已经被改了之后，卸载也撤不回那些修改。

它不会取代你现在用来写文档、做表、跑自动化的整套工具。官方也没有把它写成通用的应用商店，或可以离线使用的本地软件。现有的效率工具不必为此整站替换，只把那一个每天都要打开、而且能接受用量消耗的小工具拿来试，会更合适。若你已经有一套顺手的工具链，可继续参考 [常用 AI 效率工具](/posts/best-ai-productivity-tools/)。

## 这周可以做的四件事

### 1. 先更新桌面版，确认套餐和开关

在 Claude 的 Mac 或 Windows 应用里检查更新：macOS 走 Claude > Check for Updates；Windows 走菜单按钮（☰）下的 Help > Check for Updates。官方要求版本 6.28899.0 或更高。更新后打开一个普通 Artifact，看标题菜单、右键菜单或 Share 里有没有 Install as app。

如果没有：先确认你不在 Linux、网页或手机上；再确认这个 Artifact 不是 Docs、Slides、Sheets 模板，也不是旧格式或 Cowork 的即时 Artifact。Team 和 Enterprise 用户要请所有者或管理员查看 Organization settings > Artifacts，确认整个功能是否已打开，以及应用权限、完全访问是否被关掉。Enterprise 默认是关的，没打开就不必继续试。

已做 HIPAA 就绪配置、混合部署，或不确定零数据保留怎么覆盖应用的组织，这周先不要在生产环境里试。以控制台和组织设置为准。

### 2. 用一个丢得起的小工具试装，先不要给完全访问

挑一件就算装坏了也不影响正式工作的事，例如菜单栏提醒、倒计时，或只在窗口里展示信息的清单。用帮助中心那种直白描述即可，先看 Artifact 在 Claude 里是否可用，再选 Install as app，并在确认框里点 Install。官方也写，Artifact 可以被要求自己带一个安装按钮，但无论从哪条路径走，Claude 都会再让你确认一次。

第一次安装时，只处理它实际问到的权限。通知或菜单栏够用，就不要升到完全访问。把应用放到官方写明的打开位置，确认关掉窗口后它是否还在托盘或菜单栏里运行，以及退出方式是否符合预期。试完后到用量页看一眼，因为做应用和随后的请求都会计入套餐。

### 3. 团队先写下权限规矩，再考虑分享

如果要把应用发给同事，先约定三句话，再发安装入口：

- 默认只给到完成工作所需的最低档，完全访问必须单独审批。
- 只安装本组织成员做的应用，或本人做的应用；来源不清、请求里出现警告的，一律不给完全访问。
- 应用更新后会再次询问权限，包括自己改过的版本；从其他网站加载的代码可能不再询问，这类应用不进正式工作流。

管理员还要确认：Team 上功能默认开着，但完全访问默认关；若业务上确实需要完全访问，只给到需要的小组，并准备好转发、举报和卸载的路径。Enterprise 则先决定要不要打开整个功能，而不是默认假设已经可用。

### 4. 记下不能装的类型，避免把试点做成主流程

把不能安装的名单放在团队说明里：模板类的 Docs、Slides、Sheets，旧格式 Artifact，Cowork 的即时 Artifact，以及 Linux、网页、手机。正式文档、幻灯片和表格继续留在 Claude 里，或导出到现有软件，不要指望这周就能把它们变成桌面应用。

试跑可以在 30 分钟内结束：更新客户端、确认开关、安装一个低权限小工具、看用量、写下来源和权限档位。若打开方式不比在 Claude 里找 Artifact 更快，或权限请求已经让人不安，就停在测试，不要扩大到客户数据或正式文件目录。

## 这周做完就可以停的三句

- 菜单里还没有 Install as app，或 Artifact 属于不能安装的类型，就不把现有工作迁到桌面应用。
- 应用要完全访问、来源不是自己或本组织成员，或者请求里出现警告，这周只停在默认或应用权限，不继续升高。
- 试跑后用量明显变快，或卸载后仍不放心已经改过的文件，就把该应用卸掉，主流程回到原来的工具。

新的桌面能力以后可能还会放宽。这三句可以重复用：先看开关和版本，再用一个丢得起的小工具，最后只留下打开更快、而且权限你能接受的那一个。

## 常见问题

### 免费版现在能用 Install as app 吗？

按官方帮助中心，这个测试功能面向 Free、Pro、Max、Ultra、Team 和 Enterprise，但只在 Claude 的 Mac 和 Windows 桌面应用里，版本需要 6.28899.0 或更高。Linux、网页和手机装不了。它在逐步推送，菜单里暂时没有「Install as app」时，先检查更新；Team 和 Enterprise 还要问管理员是否已打开。

### 装上去之后，要不要给它完全访问电脑的权限？

默认不要。官方把权限分成三档：默认只做浏览器里也能做的事；应用权限才包括通知、全局快捷键、置顶窗口、菜单栏或托盘图标；完全访问则可以运行程序，并在不再逐次询问的情况下读取、修改或删除文件。完全访问只能给自己做的应用，或 Team / Enterprise 里本组织成员做的应用。Anthropic 写明安装前不会审查应用，只把完全访问给自己信任的来源。

### Docs、Slides、Sheets 能不能装成桌面应用？

不能。官方帮助中心写明：用模板做出来的 Artifact，例如 Docs、Slides、Sheets，不能安装；旧格式的 Artifact，以及 Claude Cowork 的即时 Artifact，也不能安装。这类材料仍在 Claude 里用，用法可参考我们之前写的 [Meetings、Sheets 和 Whiteboards 说明](/posts/claude-meetings-sheets-whiteboards-guide/)。

### 公司开了零数据保留或 HIPAA 配置，能不能用？

要分开看。官方介绍页写：已做 HIPAA 就绪配置的组织，以及混合部署，不能使用这个功能。帮助中心另外写：若组织为 Claude Code 开了零数据保留，需要所有者先打开 Artifacts 和 Install as app 才能安装，而且这些应用不被零数据保留覆盖。教育场景里，Claude for Teachers 和 K-12 组织不能开完全访问，安装功能也可能关闭或不可用。以管理员在组织设置里的实际开关为准。

### 安装和应用里的请求会不会另收费，会不会占用量？

官方介绍页和帮助中心都没有为这项功能单列新价格，但写明：做应用，以及应用向 Claude 发出的请求，都计入你当前套餐的用量。打开前后各看一次用量页。额度怎么估，可以接着读 [免费 AI 工具的用量说明](/posts/free-ai-tool-limits/)。
