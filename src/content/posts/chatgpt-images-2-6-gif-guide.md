## 在 ChatGPT 里现在可以做的三件事

### 做一条循环 GIF

帮助中心给的做法是：直接要一段循环动画，或上传一张草图，让 ChatGPT 把角色做成挥手这类动作。The Verge 补充了上传照片，以及生成之后可以改播放速度、逐帧看、改单个帧。博客举的用途包括：让品牌吉祥物或角色动起来，把产品图做成循环，做社媒反应图，或在拍视频之前用动态分镜看角色怎么动。简单草图也可以做成会动的角色。这些是 OpenAI 写的用途，不是本文测过的成功率。

建议你第一次就用自己的材料，而不是只用猫跳舞的示例：

1. 写清主体、一个循环动作、背景尽量简单。需要保留的颜色、衣服、包装，写进同一条提示。指南在 GPT Image 的限制里写，文字渲染仍可能放不准，包装上的字要准备人工看一遍。
2. 生成后按帮助中心去调播放速度，需要的话按 The Verge 的报道逐帧看、改某一帧，再分享。按钮文字以屏幕为准。
3. 发出去之前自己看完一个循环：动作是否跳、标志是否变形、最后一帧能否接回第一帧。博客把这种 GIF 放在视频制作之前，不要把它交成视频成片。

系统卡写，Chat 里可以用模型选择器（model picker）调节推理力度。本文没有看到选择器里的具体档位名称。API 指南里对应的规划字段叫 `complexity`，和系统卡的用词不一样，下面 API 一节再分开写，不要当成同一个按钮。

### 把参考图存成名字

帮助中心的例子可以原样照做。把狗的照片存成 Pepper。之后要一张水彩肖像时，写 @Pepper，不必把照片再传一次。X 帖只说有 reference images，没有写 Pepper 这个例子，操作细节以帮助中心为准。

这和「每次聊天都重新上传」不是同一件事。系列帖、同一吉祥物的一周内容，先存一次名字，再在新对话里用 @名字，减少每次重传带来的走样。帮助中心同时写，编辑时更能保住细节，例子就是换背景时衣服还在。正确的验收不是看模型说「已保留」，而是把衣服、标志、五官和你指定的那张参考图并排看。

博客还写，Sunburst 在中、高画质下编辑一致性更好。那是 API 模型的说法。ChatGPT 套餐里你选不到 Flare 或 Sunburst 的模型 ID 时，不要假设自己正在用哪一个。套餐内没有在 2.6 的发布说明里标出「一张图多少美元」。

参考图是帮助中心列出的 ChatGPT 功能。API 要自己在每次请求里带上图像，本文没有在模型页上看到「把图存成 @Pepper、以后只用名字」的接口。

### 生成更快，仍然要自己看编辑结果

「更快」出现在帮助中心。「大约快 50%」出现在博客和 X 帖，比较对象博客写成 than before，没有在本文看到的段落里写成相对某一个模型 ID。quality 为 low 时 Flare 最快大约 6 秒，是博客对 API 的说法，用了 as little as。不要把 6 秒写进对客户的工期，也不要把它套到 GIF 或多帧上。

图像生成指南另有一条一般限制：复杂提示可能要最多约 2 分钟。它和「最快大约 6 秒」不矛盾，一个是 OpenAI 说的下限附近，一个是指南写的复杂请求上限。你的耗时以这次请求为准。

指南同时仍把一致性写成限制：模型有时会保不住反复出现的角色或品牌元素。所以「更能保住衣服」是帮助中心对 2.6 的描述，验收步骤不能删。

## ChatGPT、Flare、Sunburst 怎么选

两个 API 模型页的定位不同，单价在本文打开时相同。Flare 的页面摘要是快速迭代的图像生成和编辑。Sunburst 的页面摘要是细致视觉工作的图像生成和编辑。输入都是文本和图像，输出都是图像。默认快照就是各自的模型 ID。两边都支持 `v1/images/generations` 和 `v1/images/edits`。Chat Completions、Responses、Batch、Videos 在两张模型页上都是不支持。

| 你要做的事 | 先用 | 依据 |
| --- | --- | --- |
| 今天做一条能分享的社媒 GIF，还要调速度或改某一帧 | ChatGPT | 帮助中心写了调速度和分享；The Verge 写了改单个帧。API 的编辑端点不支持 GIF 输出 |
| 跨对话复用同一张照片，用 @名字 | ChatGPT | 帮助中心的 Pepper 例子。API 没有看到同等的已保存名字 |
| 低画质快速试构图、试海报和产品图布局 | API `gpt-image-2.6-flare` | 模型页定位是快速迭代。博客称 quality=low 时最快大约 6 秒，并称 Flare 也改进了海报和产品图的版式 |
| 要更高画质，或连续编辑时更一致 | API `gpt-image-2.6-sunburst`，quality 用 medium 或 high | 博客原句把这两档和更高质量、更强编辑一致性放在一起 |
| 站点图标、需要可编辑路径的矢量 | API 生成端点，`output_format` 设为 `svg` | 指南写编辑端点不支持 SVG。系统卡把 SVG 写在 API |
| 在照片上圈出要改的区域 | API 编辑端点的 `markup`；ChatGPT 里已有标注能力 | 博客写 markup 本来在 ChatGPT，这次进入 API。系统卡写两边都有 photo markup |
| 要对账单、要锁定模型 ID | API，并读取返回的 usage | 套餐生图没有在 2.6 说明里标美元单价 |

博客建议：多数编辑用 low complexity，再配上你需要的画质。场景元素多、约束多时，再试 medium 或 high。指南写，两个模型的 `complexity` 只有 `low`、`medium`、`high`。省略时都用 `high`。调 complexity 不另收费。更高的 complexity 可能更慢，也可能带来你没要求的改动，所以要和你的任务对比，而不是一律拉高。编辑示例展示的是 markup、quality 和 prompt，没有在同一段示例里写上 complexity。请求若被拒绝，以接口返回为准，不要另造字段名。

`quality` 和 `complexity` 不是同一个旋钮。指南的估算说明里，2.6 与 2.5 的 Sunburst、Flare 画质选项包括 `low`、`medium`、`high`、`xhigh`、`max`。博客只把 Sunburst 的「更强编辑一致性」系在 medium 和 high 上。本文不把 xhigh 或 max 写成官方推荐的定稿档。

## 官方 token 单价：两张模型页相同

下面是 2026-11-05 打开的两张模型页，单位都是每百万 token。Sunburst 和 Flare 这五档数字相同。

| 计费项 | Flare | Sunburst |
| --- | --- | --- |
| 文本输入 | 5 美元 | 5 美元 |
| 缓存文本输入 | 1.25 美元 | 1.25 美元 |
| 图像输入 | 8 美元 | 8 美元 |
| 缓存图像输入 | 2 美元 | 2 美元 |
| 图像输出 | 30 美元 | 30 美元 |

图像指南里，GPT Image 2.5 两个模型用的也是这五档：图像输入 8 美元、缓存图像输入 2 美元、图像输出 30 美元、文本输入 5 美元、缓存文本输入 1.25 美元。2.6 的「Cost」一节把图像输出写成每百万可计费 token 30 美元。指南同时写：单价相同不等于每张图花费相同，token 消耗会随模型和画质变化。请用响应里的 `usage` 计算你自己的提示词、尺寸和画质。指南里的估算器要求显式指定 quality 和 size，`auto` 取决于生成结果，不能拿来当固定报价。

有一条不要误用。指南写，对 GPT Image 2 和 2.5，缓存输入价只适用于 Responses API 里的图像工具，不适用于直接的 Images API，包括 `/v1/images/edits`。这句话没有写成 2.6。而 2.6 的模型页把 Responses 标成不支持，实际列出的是生成和编辑两个端点。因此本文不把 1.25 美元和 2 美元的缓存价写成「直接调 Images API 就一定命中」。模型页确实列了缓存价。命中与否看账单。改预算前再打开模型页。

markup 引导的编辑，指南写与其他编辑同一套 token 单价，没有附加费。SVG 要付两笔：图像模型制作参考图的费用，以及写作模型产出 SVG 所用 token 的费用，总额取决于两边各用了多少 token。指南没有在本文看到的段落里写出那个写作模型的名字和单价，所以下面不报一个 SVG 总价。

部分图像流式输出的 `partial_images`，指南写每张部分图额外 100 个图像输出 token。GIF 和 SVG 都不支持 streaming、partial images、自定义 `output_compression` 和 `prompt_rewriter`。做 GIF 或 SVG 时不要打开 partial images 去「看看中间结果」，那不是这两条输出格式的路径。

速率限制，两张模型页都写：随用量档和账户变化，去看你的组织限额。本文没有具体的每分钟张数。

怎么把「每百万 token」算成一笔请求，和 [GPT-6.1 Terra 的单价怎么读](/posts/gpt-6-1-terra-cost-guide/) 是同一类算术：先写明哪些数字是官方单价，哪些条数是示例假设。下面的 token 条数是**示例假设**，不是 OpenAI 的统计，也不是一张图的典型值。

费用 = 文本输入 token / 1,000,000 × 5 + 图像输入 token / 1,000,000 × 8 + 图像输出 token / 1,000,000 × 30。

取一组便于心算的假设：1,000 个文本输入 token、2,000 个图像输入 token、8,000 个图像输出 token，且不把缓存价算进去。

- 文本：0.001 × 5 = 0.005 美元
- 图像输入：0.002 × 8 = 0.016 美元
- 图像输出：0.008 × 30 = 0.24 美元
- 合计 0.261 美元

若这组假设里的图像输出 token 因画质或 GIF 帧数变成另一倍，输出那一项同比变化，另外两项不变。倍数是多少，以 `usage` 为准。指南没有给出「GIF 按帧数乘以一个固定 token」的公式，本文也不编。`frame_count` 默认 9、范围 2 到 64，只说明你可以要更多帧，不说明账单一定是 9 倍静图。

批量跑之前，把单次上限、每日预算和账户硬限额分开设。做法可以沿用 [AI 自动化越跑越贵怎么办](/posts/ai-automation-cost-control/)。图像这次尤其不要只看模型页上的「单价相同」就认为 Flare 和 Sunburst 的月账单会一样。

## 四条可以照着做的流程

### 社媒用的吉祥物 GIF

适合：本周就要一条循环图，发给社交账号，人不在旁边写代码。

1. 在 ChatGPT 里用一句话写清吉祥物、一个动作、循环、不要额外文字。若你只有草图，按帮助中心上传草图再要求动作，例如挥手。若你已有定稿插画，The Verge 的报道支持上传照片再做成 GIF。
2. 生成后调播放速度。需要某一帧不跳，再按 The Verge 所说去改那一帧。改完看完整循环，而不是只看封面帧。
3. 检查三样东西：衣服和标志是否还在，循环接头是否闪一下，画面里有没有你没要求的文字。文字不稳是指南里的一般限制。
4. 分享前确认这条素材就是 GIF。不要在文案里写成视频广告已完成。博客允许的下一步是拿它做视频制作前的动态分镜，那是另一道制作，不是这次按钮的输出。

套餐额度在产品里看过再批量做一周的内容。2.6 没有公布「每天几条 GIF」。

### 产品图循环

适合：已有产品照片，想要一条短循环，而不是重拍。

博客的说法是把产品图变成抓眼的循环。The Verge 写可以用上传的照片做 GIF。操作上就是上传现有产品图，提示里写清要保留的包装颜色和形状，以及你希望的动作范围。不要在提示里假设包装上的小字一定清晰，指南写精确文字仍可能有问题。生成后把包装文字和原图对一下，错了就改提示重来，不要用修图软件外面的承诺代替核对。

API 侧若要锁住模型，用生成端点而不是编辑端点出 GIF。指南写：`output_format` 设为 `gif`；在提示里写主体、动作和希望的循环；`frame_count` 为 2 到 64，默认 9；`frame_duration_ms` 为 20 到 2000 毫秒，按 10 毫秒取整，默认 200。`size` 可以是 `auto`，或宽高都为正、且是 16 的倍数。文档里的灯笼例子用 Sunburst、`frame_count=9`、`frame_duration_ms=200`，并写角色在 1.8 秒后回到起始姿势。1.8 秒是这组参数的乘积（9 × 200 毫秒），不是所有 GIF 的长度。默认值刚好也是 9 和 200，所以不改参数时，文档给出的默认时长就是 1.8 秒。帧数、单帧尺寸和条数还要落在模型的尺寸限制和总像素预算里，超出就减少帧数、缩小尺寸或减少条数。

这条路径产出的是整段新 GIF。它不是「打开旧 GIF，只改第 4 帧」的编辑接口。单帧修改走 ChatGPT（The Verge）。编辑端点不要用来出 GIF。

### 用保存的参考图维持同一个角色

适合：同一角色要发多条，又不想每次重传照片。

1. 按帮助中心，把照片存成一个短名字。例子是 Pepper。
2. 新对话里用 @Pepper，并写清这次只改什么，例如水彩、背景换成工作室。衣服、体型和标志写进「不要改」的那一句。
3. 并排对比参考图和结果。帮助中心用换背景时衣服还在做例子，你就用这个例子验收。
4. 角色要进 API 流水线时，每次请求带上那张图。指南写，markup 只作用于第一张输入图，额外的图当作参考。不要以为 ChatGPT 里的 @Pepper 会自动出现在 API 账户里。

### 用 API 做站点图标和圈选改图

适合：要放进网页的 SVG，或要在一张已有照片上指定区域改颜色、改物体。

SVG 按指南这样做：

- 只走 `POST /v1/images/generations`，`output_format` 设为 `svg`，`n` 设为 1。
- 用途是需要可编辑路径、形状和颜色的图形，例如图标和插画。指南用同一条面包店标志提示，分别展示了 Flare 和 Sunburst 的 SVG。
- API 会先做一张参考图，再用它产出 SVG。`quality` 控制的是这张参考图。
- 把返回的 `data[0].b64_json` 按 base64 解码，得到 UTF-8 的 XML，存成 `.svg`。
- 结果是静态矢量：不支持脚本、外部资源，也不嵌入光栅图。编辑端点不支持 SVG，SVG 也不能当作后续图像编辑的光栅输入。
- 费用是参考图的图像模型费用加上写作模型的 token，本文不报总价。上线前用一次真实 `usage` 记一笔，再决定是否批量。

圈选改图按指南这样做：

1. 原图作为第一张输入图。
2. 另做一张透明 PNG，只画圆、草图或其他标注。旋转之后，标注层和第一张图的宽高必须相同。PNG 里要有透明像素，不要先压扁到原图上。
3. 编辑端点把这张 PNG 作为 `markup` 送出。多部分表单可以直接传文件。JSON 则用只含 `image_url` 或 `file_id` 之一的对象。
4. `prompt` 写清要改什么、要保住什么。指南的例子是把红圈里的条纹花瓶改成钴蓝色陶瓷，保住形状、干花和厨房其余部分，并去掉红圈。
5. 标注只作用于第一张图。第一张图和标注层各自最多 16,777,216 像素，标注文件还有 50 MB 上限。不要把 `markup` 和 `mask` 或 `prompt_rewriter` 一起用。
6. 试稿可以用文档示例里的 `gpt-image-2.6-flare`。定稿若要博客说的那种编辑一致性，换 Sunburst，并把 quality 设为 medium 或 high。多数编辑按博客把 complexity 设为 low，不要依赖省略后的默认 high。

改完先看圈外有没有被连带改掉。指南提醒更高 complexity 可能引入不想要的变化，默认又是 high，这一条值得写进调用代码的注释里。

## 额度、安全和不要说成视频

### 套餐生图限额：先标成推测

Images 2.5 在帮助中心 2026 年 9 月 8 日的条目里写：现有生图限制不变。Images 2.6 在 2026 年 11 月 4 日的条目里没有写新限额，也没有再写一遍「限额不变」。

**推测，不是事实：** 若 OpenAI 没有另行宣布，套餐内的生图次数可能仍是 2.5 那句之后的状态。请打开你当前方案在产品里的 Images 额度，以页面上的剩余和重置为准。本文不提供 Plus、Pro、Business 或免费档的生图张数，也不提供套餐内单张图的美元价格。发布说明里没有这些数字。

12 月起部分方案的 ChatGPT 与 Codex 用量合并，是另一件事，见 [ChatGPT 与 Codex 额度将合并](/posts/chatgpt-codex-shared-usage-pool/)。那篇依据的帮助中心文章讲的是共享池和 token，入口写的是 Settings → Usage。Images 2.6 的发布说明没有把生图次数写进同一句。两处都要看，不要用聊天剩余额度去推算还能做几张 GIF。额度类信息怎么核对，也可以再看 [免费 AI 工具怎么挑](/posts/free-ai-tool-limits/)。

API 侧的限额随组织变化。套餐里的促销 API 额度如果存在，也不要当成图像模型的免费张数，以你账户里的优惠条款为准。2.6 的 changelog 没有写赠送张数。

### 系统卡里和 GIF 有关的限制

系统卡发布于 2026 年 11 月 4 日，地址是 [ChatGPT Images 2.6 System Card](https://deploymentsafety.openai.com/chatgpt-images-2-6)。它写：安全栈基于 Images 2.5，另外为 GIF 加了防护。GIF 会带来静图里不明显的风险，包括带有性意味的动作，以及跨帧才能看出来的有害含义。GIF 的规则会比静图更宽地拦住一些类别，用来覆盖推断出来的动作。动作类违规仍然难抓，防护可能漏掉。

同一份卡用 3,077 条故意写来违规的请求做离线评估，并写明这不代表线上违规请求有多常见。和各自的 2.5 基线比，未被拦住的违规输出比例：Sunburst 从 1.92% 到 1.72%，Flare 从 1.49%（46/3,077）到 2.14%（66/3,077）。卡上写这两个总体差异都没有统计显著性。Flare 在审核前被评为不违规的比例从 78.36% 降到 75.04%，这一下降有统计显著性。这些数字只说明评估集上的审核结果，不能写成你的品牌素材被拒率。

实用含义很窄：营销 GIF 不要去踩「动作本身才构成违规」的内容；被拦住就改提示或换输入图。指南写，审核拦截属于需要改请求的用户错误，不要原样自动重试。面向访客的提示保持笼统即可。本文不讨论怎样绕过这些检查。

系统卡还写，两个模型都没有跨过生物和网络安全的 High 门槛，但仍按预防性原则，沿用把模型当作具有 High 生物能力来处理的缓解措施。图像模型不会因为这次更新变成视频模型，也不会变成可以执行代码的智能体。具体评估以系统卡为准。

来源方面，系统卡写继续使用 C2PA 元数据，并在 ChatGPT、Codex 和 API 里加入 Google DeepMind 的 SynthID 水印。读者可以用 OpenAI 的公开核验工具检查支持的文件。本文抓取的系统卡正文没有给出该工具的网址，请从系统卡页面进入。对外发布的 GIF 和产品图，按你原来的素材授权流程走，水印不能代替你对照片和商标的使用权。

### 明确不做的承诺

- 不把 GIF 写成视频，也不把动态分镜写成已经完成的广告片。
- 不把「快 50%」和「大约 6 秒」写成第三方复测或合同工期。
- 不编造 ChatGPT 套餐的生图单价和张数。
- 不编造没有在帮助中心、The Verge 或系统卡里出现的按钮名称。
- 不把 Flare 和 Sunburst 的相同 token 单价写成相同的单张成本。

## 和已经写过的选型怎么放在一起

图像生成是一种任务，不是新的默认模型。难的、要连续改很多遍还不走样的定稿，按博客把 Sunburst 和 medium 或 high 画质放在一起试。要在对话里快速出一条 GIF，留在 ChatGPT。要进仓库、要 SVG、要对 `usage` 的，走 API，并把 complexity 显式写成 low，除非这次画面确实挤。

文字模型那边，便宜档怎么替换、什么时候不要替换，Terra 那篇已经写过算法。图像这次的新信息是：两个模型页单价相同，变量在 token 数、画质、帧数，以及缓存价能不能用在直接的 Images API 上。后者本文标成未在 2.6 的句子里证实。

套餐额度仍按产品内页面记，不要和 12 月的共享池混算。模型分工仍按前面那篇「按任务分工」的表来填：试一次自己的吉祥物、一次自己的产品图、一次自己的图标，再决定哪一条留在 ChatGPT，哪一条进 API。

## 常见问题

### ChatGPT 里现在就能做 GIF 吗？要哪个套餐？

官方博客写，Images 2.6 在 2026 年 11 月 4 日起于 ChatGPT 和 Codex 全球可用，覆盖全部订阅档，桌面、手机和网页都有。帮助中心把 GIF 写成正在推出：可以要循环动画，或上传草图让角色挥手，然后调播放速度并分享。The Verge 写也可以用上传的照片，并能改单个帧。账号里还没有入口时，按 rollout 理解。

### Flare 和 Sunburst 的 API 单价一样吗？

2026-11-05 的两张模型页上，五档单价相同：文本输入 5 美元、缓存文本输入 1.25 美元、图像输入 8 美元、缓存图像输入 2 美元、图像输出 30 美元，都是每百万 token。指南写消耗的 token 可以不同。缓存价是否适用于 2.6 的直接 Images API，指南没有写明，模型页虽列出缓存价，但把 Responses 标成不支持。以账单为准。

### 套餐里的生图次数这次变了吗？

2.6 的条目没有说。2.5 在 2026-09-08 写过现有生图限制不变。限额是否仍然没变，是推测，不是 2.6 的官方承诺。到产品里看当前 Images 额度。不要把 API 单价换算成套餐里一张图的价格。

### API 能改 GIF 的每一帧，或把结果导出成视频吗？

视频端点对这两个模型不支持。GIF 在生成端点用 `output_format=gif` 整段生成，编辑端点不支持 GIF 输出。`frame_count` 和 `frame_duration_ms` 是生成参数。改某一帧的播放，The Verge 写的是 ChatGPT。

### 快 50% 和大约 6 秒，是第三方测出来的吗？

不是。两者都是 OpenAI 在博客里的说法，X 帖也写了快 50%。6 秒是 quality 为 low 时 Flare 的 as little as，不是每张图、也不是每条 GIF 的承诺。复杂提示在指南里仍可能到大约 2 分钟。
