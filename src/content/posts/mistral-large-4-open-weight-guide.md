2026 年 10 月 29 日，Mistral 开放了 Mistral Large 4 的权重，代号 Le Chonk。公告写的是：本月早些时候它已经以公开预览发布，这次放出的是又经过三周额外强化学习之后的改进版。文档模型页页眉写着 2026 年 10 月 6 日和 Public Preview。两页我都打开核对过。本文不把「10 月 6 日」和「三周」算成一个精确天数。

它和同一周另外两则模型新闻的差别，在于你现在就能调用，而且权重可以下载。Gemini 4 Carbon 对多数账号还没开放，见 [Gemini 4 Carbon：多数人还用不上](/posts/gemini-4-carbon-what-it-means/)。GPT-6.1 Terra 是另一家的闭源降价，记账方法可以对照 [GPT-6.1 Terra 的价格和换档](/posts/gpt-6-1-terra-cost-guide/)，单价不能搬过来。模型按任务分工的总原则，仍是 [本周 AI 模型按任务分工](/posts/october-ai-model-roles/)。这篇只回答 Large 4：发生了什么，账怎么算，什么场景先试 API，什么机器档才谈自托管，以及许可证里的模型即服务（MaaS）要怎么自检。

## 这次发布具体是什么

按 Hugging Face 模型卡，Mistral Large 4 是原生多模态的混合专家模型（MoE）：总参数约 1 万亿，每个 token 激活约 490 亿（49B），把嵌入层和输出层算进去约 520 亿（52B）。文档模型页写成总参数 1.05T、活跃参数 52B，并单列一个 1.6B 的视觉编码器。两页用词不同，都落在「大约一万亿参数、每个 token 活跃大约五百亿」这一档。模型卡还写了路由方式：128 个可路由专家里每个 token 选 4 个，另外始终有 1 个共享专家。一万亿是参数库存，不是每个 token 都把一万亿参数算一遍。API 单价是定价页上的另一组事实，不要从参数规模直接推账单。

模型卡写明：上下文 100 万 token；输入是文本和图像，输出是文本；能看图像、图表、技术图纸和文档。它原生支持 160 多种语言，包括欧盟全部官方语言。推理分三档，公告和模型卡一致：`low`、`medium`、`high`，默认 `high`。公告给三档的建议用途是：Low 做简单任务，并用来替换原来的 None 档；Medium 做日常任务；High 做最难、要高精度的任务。Hugging Face 博客在 Transformers 一节写：推理不能关掉，把 `reasoning_effort` 设成 `none` 仍会按 high 跑。两处合在一起，实际含义是：没有一个「完全不推理」的开关。日常任务要自己改成 Medium，否则默认走 High。

训练地点以模型卡为准：在 Mistral 位于欧洲的自有数据中心，用 3,800 张 NVIDIA Grace Blackwell GPU 从头训练。公告写的是「在欧洲基础设施上从头训练」，并把它说成主权 AI 的来源说明。这 3,800 张是训练规模。下文的推理示例是另一组数字，不要把训练集群当成你要买的机器。

权重和调用入口，按公告：Mistral Studio、Mistral API、OpenRouter；要自己掌握部署，就从 Hugging Face 下载，用 vLLM 或 SGLang。也可以走 NVIDIA 托管端点，或用 NVIDIA NIM 容器配合 vLLM。不想自建机房、又要托管服务的，公告写可以通过 Microsoft Foundry，并为 Azure 开发者提供私有部署选项。模型卡把 API 上的模型名写成 `mistral-large-4`。官方编程助手 Vibe 可以选择这个名字走 API，也可以把配置指到你自己的 vLLM。当天的行业汇总 [DailyCited（2026-10-30）](https://dailycited.com/d/2026-10-30/) 记录了 Hugging Face 在 10 月 29 日发布这批权重，并写到 FP8、NVFP4 和 GGUF。

Hugging Face 博客把官方权重量成两档：FP8 和 NVFP4。模型卡写 NVFP4 显存更小、推理更快，并称性能相同，目标是 Blackwell GPU。GGUF 来自 Unsloth 和 llama.cpp 团队。博客列出的量化档包括 `IQ2_XXS`、`Q2_K`、`Q4_K_M`、`NVFP4`、`Q8_0` 和供继续转换的 `BF16`。当天的 DailyCited 汇总写 transformers v5.22.0 提供了首日支持。Hugging Face 博客写的是升级 transformers 后即可使用，模型卡上的安装示例则是从 GitHub 的 main 分支安装。自托管时以模型卡当前命令为准，页面会改。

许可证公告概括成：基于 MIT 修改的 Mistral Ecosystem Open-Weight License，可免费使用、修改、微调和商用，做模型即服务的企业要另取商业许可。仓库里的 LICENSE 比这句摘要多几条边界，见下文专节。公告还说完整技术报告即将发布。本文没有引用那份尚未读到的报告。

网络安全还有一条产品边界。公告说，他们在预览期看到模型会拒绝针对在线目标的黑盒攻击，同时认为模型有被用来实施真实攻击的潜力，因此还在改防护，之后几个月会继续更新。面向渗透测试、漏洞评估和红队的专用变体，只以预览形式提供给经过审查的企业设计伙伴（公告点名 Orange Cyberdefense），测试限于自有或明确授权的系统。Hugging Face 上这份公开权重，不是那个专用变体。防御向的基准分，不能换成「可以对生产系统做未授权测试」。

## 为什么值得单独看：权重、价格、数据落在哪、许可写到哪

**权重可以离开厂商的 API。** 公告把主权写成：组织可以检查、定制、在自己的基础设施上部署，不必依赖 Mistral 来提供 API。同一页也写了，主权不一定等于自托管；只要求部署满足你的控制条件时，可以走 Microsoft Foundry 的托管和私有部署。对中小团队，这句话的用法是：先决定数据能不能出你指定的环境。能出，就用 API 把质量测完。不能出，再看你有没有下文那类机器，或者让云厂商的私有部署给你报价。报价本文没有看到，不编。

**价格已经是公开价，不是「联系销售」。** 公告写，即日起 API 为每百万 token 输入 0.70 美元、缓存输入 0.07 美元、输出 2.10 美元。定价页在本文核对时把同一行写成 $0.7、$0.07、$2.1。缓存输入是普通输入的十分之一，输出单价是普通输入的 3 倍。定价页没有按上下文长度再分一档加价，本文不假设长上下文另有倍数。文档模型页列出了批处理，定价表没有单独的批处理折扣，本文不假设批处理更便宜。

同一张定价页上，便于对照的另外三行（仍是本文核对时的页面，不是质量排名）：Mistral Large 3 为 $0.5 / $0.05 / $1.5，Mistral Medium 3.5 为 $1.5 / $0.15 / $7.5，Z.ai GLM 5.3 为 $1.4 / $0.14 / $4.4。同样的 token 结构，Large 4 比 Large 3 贵，比 Medium 3.5 和这张页上的 GLM 5.3 便宜。贵和便宜都只对「token 数相同」成立。公告说编程指数上 Large 4 平均每任务少用 47% token，但没有给出绝对 token 数，也没有说少的是输入还是输出。下面的例子不乘这 47%。

**许可证不是「MIT，所以可以拿去卖推理 API」。** 公告的「唯一条件」是摘要。仓库 LICENSE 还有保留版权声明、MaaS 的定义，以及内部使用和官方产品的例外。卖 API 的公司和只在自己员工里用模型的公司，不在同一条规则里。检查表在后文。

## 对正在用 AI 干活的人，这周意味着什么

默认模型先不动。Large 4 适合加进对比表的新列，不适合作为「全公司今晚切换」的理由。一次只换一类任务，才能看出差别。这个做法和分工那篇相同。

值得先用 API 试的，是你这周本来就要做、而且一天内能由人判断对错的活：

- 一小段你确实打算改的代码。FrontierCode 想测的是「维护者愿不愿意合并」。你能做的缩小版，就是看补丁能不能进你的分支。编程助手如果已经在 GitHub Copilot 里，选档和对账看 [Copilot Fusion 的计费](/posts/github-copilot-fusion-ga/)。两篇榜上的分数不要相减，产品和公布日期都不同。
- 一张图表、一张技术图纸、一页版式乱的扫描件。模型卡写了这些视觉输入。输出仍是文本，不要指望它交回一张改好的图。
- 一段要保持术语的多语言说明。160 多种语言是模型卡上的能力描述，你的术语表仍要你自己提供。
- 一张财务或对账表格的草稿。73.3% 是 Finch 上的厂商自报，用来决定「值得拿自己的表试」，不用来当会计准确率。

先不要交给它的：付款、对外发送、改权限；把整个代码库塞进 100 万 token 的上下文再看账单；对没有授权的系统做攻击性测试。合并代码之前要有人看。安全基准再高，也只说明对方在那组题目上的拒绝或抵御比例。

三档怎么选，按公告的用途，不按想象中的倍数：简单问答用 Low，日常写作、抽取、改写用 Medium，要来回核对的难题再用默认的 High。公告没有公布每一档相差多少 token。High 是默认值，不改参数就会落在这一档。自托管时，模型卡写明 `max_completion_tokens` 同时包含推理 token 和可见回复。API 是否把推理 token 计入输出，定价页没有单独说明，以控制台用量为准。可见回复很短、账单很长，就先把档位从 High 降到 Medium，再决定是不是模型本身的问题。

## 按官方单价算的两笔账

公式只有一行，单位都是「百万 token」：

费用 = 新输入 × 0.70 + 缓存输入 × 0.07 + 输出 × 2.10

100 万 token 才是 1。下面的次数和 token 条数都是**示例假设**，用来演示乘法，不是 Mistral 的统计，也不是你的账单。

**第一笔：先花大约 1 美元，决定要不要继续。** 假设一周试 30 次代码修改，每次新输入 2 万 token，不走缓存，输出 4,000 token。合计新输入 60 万（0.6 个百万 token），输出 12 万（0.12）。

- 输入：0.6 × 0.70 = 0.42 美元
- 输出：0.12 × 2.10 = 0.252 美元
- 合计：0.672 美元

这 0.672 美元只在「每次输出 4,000 token」时成立。若默认 High 把每次输出拉到 10,000 token（这是示例假设，不是官方公布的档位倍数），30 次输出合计 30 万 token，也就是 0.30 个百万 token，输出费用为 0.30 × 2.10 = 0.63 美元，加上输入 0.42 美元，合计 1.05 美元。算法不变，变的是控制台里的输出量。

**第二笔：按月看结构，看钱花在输出还是缓存。** 假设每月 2,000 次「读一份材料并写修改意见」，每次新输入 6,000、缓存输入 2,000、输出 1,500。月合计是新输入 1,200 万（12）、缓存输入 400 万（4）、输出 300 万（3）。

- Large 4，缓存命中：12 × 0.70 + 4 × 0.07 + 3 × 2.10 = 8.40 + 0.28 + 6.30 = 14.98 美元
- Large 4，缓存没命中，那 400 万按普通输入：16 × 0.70 + 3 × 2.10 = 11.20 + 6.30 = 17.50 美元
- 同一 token 结构、缓存命中，定价页上的 Large 3：12 × 0.5 + 4 × 0.05 + 3 × 1.5 = 6 + 0.2 + 4.5 = 10.70 美元
- 同一结构，Medium 3.5：12 × 1.5 + 4 × 0.15 + 3 × 7.5 = 18 + 0.6 + 22.5 = 41.10 美元
- 同一结构，定价页上的 GLM 5.3：12 × 1.4 + 4 × 0.14 + 3 × 4.4 = 16.8 + 0.56 + 13.2 = 30.56 美元

14.98 美元里有 6.30 美元是输出，约占 42%。缓存省下的是 17.50 减 14.98，也就是 2.52 美元，全部来自那 400 万重复输入：按 0.70 计是 2.80 美元，按 0.07 计是 0.28 美元。系统提示、字段说明、评审清单这些逐字重复的前缀，才有机会命中。每次都把单号、时间戳拼进前缀，0.07 那个单价不会出现。怎么看重复比例，沿用 [AI 自动化越跑越贵怎么办](/posts/ai-automation-cost-control/)：先统计一周输入里有多少是逐字相同的。

如果 High 把月输出从 300 万 token 拉到 600 万，Large 4 在缓存命中时变成 14.98 + 3 × 2.10 = 21.28 美元。这仍是示例假设，不是官方的档位倍数。

和 Large 3 比，同样的 token 每月多大约 4.28 美元（14.98 减 10.70）。值不值，取决于你那 2,000 次里返工有没有减少，而不是取决于 48% 这个指数。和 Medium 3.5 比，同样 token 少 26.12 美元，前提仍是质量你能接受。GLM 5.3 那一行只说明「在 Mistral 这张定价页上、token 相同时」Large 4 更便宜。公告里的 47% 若在你的任务上出现，要按实际少掉的输入和输出重算，不要在 30.56 上直接乘 0.53。

自托管的电费、折旧和云主机月租，公告、定价页和模型卡都没有给出。本文不算这笔固定成本。调用量很小的时候，上面第一笔那种按次 API 更符合「只为实际 token 付钱」。调用又大、数据又不能出门，再拿一周真实 token 去对机器报价。这个判断和成本控制那篇一致，只是把 Large 4 的机器档写具体。

## 什么情况才考虑自托管

先满足两个条件里的至少一个：数据必须留在你指定的环境里，或者你必须在不依赖 Mistral API 的前提下做定制和微调。两个都不成立，API 就够做完这一周的对比。模型卡写了一句直接的建议：本地服务效果不理想时，优先用官方 API。

来源没有写「FP8 全量权重至少要多少 GB 显存」，也没有写一张消费级显卡的最低配置。能核对到的是部署示例和他们公布的速度。示例不是最低配置，也不是对你机器的承诺。

| 来源中的部署 | 机器 | 上下文怎么配 | 来源写的速度或限制 |
| --- | --- | --- | --- |
| Hugging Face Inference Endpoints 的现成方案 | 8 张 NVIDIA H200，FP8，张量并行加专家并行，并打开模型自带的 DSpark | 最多约 13.1 万 token，最多 16 路并发 | 单请求、1K token 提示的首 token 约 0.6 秒，生成约 65 token/秒；聊天且草稿被接受时约 120 到 138 token/秒。4 条 1.6 万 token 提示同时预填充，合计约 4,300 token/秒，首 token 8 到 9 秒。1,000 段 ShareGPT 对话的总生成约 480 token/秒 |

| Hugging Face 博客的 vLLM NVFP4 命令 | 张量并行 8，并写明需要 NVIDIA Blackwell | 示例把 `max-model-len` 设为 131072 | 命令本身，没有附这组的速度 |

100 万 token 是模型卡上的上下文能力。上表里把服务长度配在 13.1 万、3.2 万，或者在 80 万时把生成速度打到每秒 3 个 token。计划「把整仓整月文档一次塞进自托管」之前，先看你要的是哪一行的速度。2-bit 能在 512GB 统一内存上跑，是量化权重。博客给了速度，没有说 Q2_K 和 FP8 的基准成绩相同。微调示例在 Hugging Face 博客里跑在 8 张 B300 上，用的是 FP8。那同样是示例机器，不是微调的最低配置说明书。

因此，自托管的进入条件可以写成三句：数据或定制要求你离开 API；你已经有上表某一行的机器，或者云厂商按那一档给你的报价你算得过；你做完下一节的许可检查，确认自己不是在没有商业许可的情况下对外提供模型即服务。三句缺一句，就继续用 `mistral-large-4` 的 API。

## 用自己的任务做一周对比

厂商分数用来选「哪一类活值得试」，不用来当及格线。从上周的真实工作里抽三类，每类 10 条，一天内能由人判对错：

1. 一段你本来就要改的代码。分别交给现在的编程模型和 `mistral-large-4`。Medium 跑一遍，High 再跑一遍。只记三件事：补丁能不能直接用，返工几分钟，输入和输出 token。
2. 一张带数字的图或一页扫描件。看抽出的数字有没有错。错一个关键数，这条算不采纳。
3. 一段会对外的文字，例如报价说明或客服草稿。模型只出草稿。发送仍由人点。这一类用来确认你没有把新模型接到自动发送上。

记录表五列就够：日期、任务类型、档位、人是否采纳、token 和按上一节公式算出的费用。一周结束只允许一个变化：某一类任务的默认模型改成 Large 4，或者维持原样。两类一起换，你就分不清是模型的差别还是任务的差别。

30 条代码样本若接近第一笔账的假设，API 花费会在 1 美元上下。花费到了几美元、采纳率没有升高，就停在这一类，不要为了 19.7% 去改生产默认模型。采纳率升高、返工时间下降，再把这一类的调用从旧模型挪过来，并继续记一周账单。输出 token 明显高于可见回复时，先降档，再谈换模型。

## 许可证自检：公告的一句话，不够用来上线

公告写：可以免费使用、修改、微调和商用，唯一条件是经营模型即服务的企业，在商用前向 Mistral 另取商业许可。我打开了模型仓库里的 LICENSE。它自称修改过的 MIT，赋予的权利包括使用、复制、修改、合并、发布、分发、再许可、出售副本，以及运行、部署、继续训练和做衍生作品。后面有条件。判断时以英文原文为准，下面是对照用的中文转述。

条件 1：副本或模型的重要部分，要带上版权声明和许可声明。

条件 2：被许可方或其关联公司如果经营模型即服务，则在把模型或衍生作品用于任何商业目的之前，必须与 Mistral 另签商业许可。联系表是 [mistral.ai/contact](https://mistral.ai/contact/)。

许可证对模型即服务的定义是：以任何方式（例如 API 或托管端点）让第三方使用模型或其衍生作品做推理或后训练，并且该第三方能对输入、参数或训练数据行使有意义的控制。定义明确排除两类：模型能力只嵌在具体功能或流程里的终端用户产品；仅仅把请求转到别人托管的模型。

许可证第 3 条写明，第 2 条的要求不适用于两类情况：内部使用，也就是不把模型或衍生作品提供给第三方；以及通过 Mistral 官方产品使用模型。

许可证末尾写明，模型和任何输出按「现状」提供，不作担保。本文不是法律意见。灰色地带用联系表问 Mistral，不要用一篇文章替你签。

上线前用这七问过一遍，每问只回答是或否：

1. 调用是否只发生在 Mistral 的官方产品里，例如他们的 API 或 Studio？是，则许可证写明第 2 条不适用。权重如果被你再分发，第 1 条的声明仍然要留着。
2. 权重是否只在公司内部使用，员工之外的人接触不到模型？是，则属于内部使用例外。
3. 产品是否只把模型嵌在一个具体功能里，用户不能自己改参数、不能提交训练数据、也不能把它当成通用推理接口？许可证把这类终端产品排除在 MaaS 定义之外。
4. 你是否只是把用户请求原样转到别人已经托管的模型，自己不托管这份权重？许可证把这种转发排除在定义之外。
5. 你或关联公司是否对外提供 API 或托管端点，客户能自己决定输入、采样参数，或拿它做后训练？这落在定义里面。商用前要先拿到商业许可。
6. 微调之后，是否把微调结果再做成客户可调的推理服务？许可证写的是模型及其衍生作品，不只是原始权重。
7. 「有意义的控制」你拿不准？先不要上线。用联系表问。关联公司也算在第 2 条里，不能用子公司的名义绕开。

只做内部知识库问答、员工写稿、自己仓库的代码草稿，并且不对客户开放一个「自带提示词的模型接口」，通常落在第 2 问。把开放权重包成按 token 收费的公共 API，落在第 5 问。两者不要写成同一句「我们商用了所以没问题」。

## 这周可以执行的决定

用三句话收束，每句都有上面的数字或步骤撑着。

API 试跑按 0.70、0.07、2.10 这组单价算。30 次、每次输入 2 万、输出 4,000、不缓存，示例结果是 0.672 美元。你的输出更长，就按同一公式替换输出那一项。月度示例里，缓存命中是 14.98 美元，其中输出占 6.30 美元。预算用你自己的 token，不用 48% 或 19.7% 去乘。

自托管只在数据或定制要求你离开 API、而且机器接近来源里的示例时才进入采购：8 张 H200 这一档的 FP8 服务、Blackwell 上的 NVFP4、512GB 统一内存上的 2-bit，或 4 张 RTX 6000 Pro 上博客测过的那些量化。没有最低显存的官方数字。模型卡建议本地效果不好就用 API。

许可按 LICENSE 的七问做，不按公告的「唯一条件」四个字做。对外提供可调的推理服务，先走联系表。内部试用 API，模型名用 `mistral-large-4`，档位从 Medium 开始，一周后只改一类任务。

## 常见问题

### 现在就能用 Mistral Large 4 吗？一定要自己买 GPU 吗？

能用。多数团队先走 API。公告列出的入口包括 Mistral Studio、Mistral API（`mistral-large-4`）、OpenRouter、Microsoft Foundry 和 NVIDIA NIM，以及从 Hugging Face 下载后用 vLLM 或 SGLang 自托管。模型卡建议本地服务不理想时用官方 API。

### 一张普通游戏显卡能不能跑完整权重？

来源没有给出这个配置。博客写 2-bit 量化可以在一台 512GB 统一内存的 Apple Silicon Ultra 上跑，其余量化需要分布式推理。常见示例是 8 卡，或 8 张 H200 的托管方案。

### 把模型嵌进自己的产品，要不要另签商业许可？

内部使用和只通过 Mistral 官方产品调用，许可证写明不适用 MaaS 条款。对外提供能让第三方控制输入、参数或训练数据的推理或后训练，商用前要另签，入口是 mistral.ai/contact。只嵌在具体功能里的终端产品，许可证把它排除在定义之外。拿不准先问。本文不是法律意见。

### 19.7%、48% 和 41% 能当成我的代码通过率吗？

不能。它们是公告里的厂商自报。模型卡同样写了编程指数 48%。博客的 49.8% 和 Terminal-Bench 的 28.3% 与公告不一致。用你自己的采纳率、返工时间和 token 做验收。

### 文中的 API 价格以后还准吗？

不保证。以公告和本文核对时的定价页为准：输入 0.70 美元、缓存输入 0.07 美元、输出 2.10 美元（每百万 token）。改预算前再看一次定价页。文中的调用量都是示例假设。
