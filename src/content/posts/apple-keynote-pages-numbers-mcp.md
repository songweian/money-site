2026 年 10 月 27 日，苹果宣布 Apple Creator Studio 更新。Keynote、Pages、Numbers 新增 beta 版智能助手，基于苹果自家模型和 OpenAI，能理解当前打开的文档。Keynote 里它帮忙设计、做动画、修改幻灯片；Pages 里起草、重组、润色文字；Numbers 里计算、可视化、整理数据，推荐合适的图表类型并给出一键预览，还能用世界知识生成自定义表格。

同一批更新给这三款应用加上 Model Context Protocol（MCP）。外部 AI 代理和工具可以读取文档内容、执行编辑，并在应用内执行自动化操作。MCP 需要 macOS 27 或更高版本，仅限 Mac。内置助手则需要支持 Apple Intelligence 的设备，系统为 iOS 27、iPadOS 27 或 macOS 27 及以上，目前仅限美式英语。

更新将于 11 月在 App Store 作为现有订阅者的免费更新推出。苹果没有给具体日期。本文只处理这三款办公应用和外部代理。新闻稿里同时还有 Final Cut Pro、Logic Pro、Pixelmator Pro 的更新，剪辑、音乐和图像工具不在这里展开。

## 这次分别放开了哪几件事

助手和 MCP 容易被收成「苹果办公软件支持 AI」。新闻稿把它们写成两套条件，核对的时候要分开。

| 能力 | 苹果新闻稿写明的范围 | 公开的系统与语言条件 |
| --- | --- | --- |
| Keynote、Pages、Numbers 的内置助手（beta） | 理解当前文档。Keynote 做设计、动画和修改；Pages 起草、重组、润色；Numbers 计算、可视化、整理数据，推荐图表并一键预览，用世界知识生成自定义表格 | 支持 Apple Intelligence 的设备；iOS 27、iPadOS 27 或 macOS 27 及以上；仅美式英语 |
| 三款应用的 MCP | 外部 AI 代理和工具读取内容、执行编辑、在应用内执行自动化 | macOS 27 或更高，仅限 Mac。脚注没有把 MCP 写成必须是 Apple Intelligence 设备 |
| Keynote 交换格式（.keyx） | 基于 JSON 的开放包格式，供外部工具、开发流程和 AI 代理读取演示文稿 | 新闻稿把它放在 Keynote 的新格式里。9to5Mac 写道，苹果称所有用户都能使用这一格式 |

heise 和 iThinkDiff 使用的系统名称是 macOS 27 Golden Gate。苹果新闻稿里，Golden Gate 出现在 Logic Pro 助手的脚注；Keynote、Pages、Numbers 的脚注写的是 macOS 27 或更高。对外沟通时用脚注里的写法，避免和 Logic Pro 的条件混成一条。

.keyx 的全称是 Keynote Interchange Format。iThinkDiff 说明，标准 Keynote 文件是一个压缩包，媒体之外还有经过 Snappy 压缩的 Protobuf 文件（.iwa）来保存文字和结构，外部工具以前要靠逆向解析，版本一变解析就可能失效。.keyx 改成可读的 JSON 包，就是为了让外部工具和代理直接读演示文稿。同一篇文章写明：目前只宣布 Keynote 有这种交换格式，Pages 和 Numbers 有 MCP，没有对应的开放文件包。独立开发者如果想在应用外面处理文稿，演示文稿可以等 .keyx，文稿和表格要等 MCP 在自己的 Mac 上出现，不要假设三款应用都有同一种离线文件。

9to5Mac 在 10 月 22 日引用了当时的更新说明，列出了更细的动作。Pages 包括起草段落、调整语气、用自然语言生成图片和形状，以及检索较新的信息写进文档。Keynote 包括生成幻灯片、演讲者备注、图片和形状。Numbers 包括生成表格、图表建议和公式方面的帮助。作者同时写道，自己更新全部 iWork 应用后还没有看到智能助手，并推测可能要等服务端开关。10 月 27 日的新闻稿把 Creator Studio 这次更新的上架时间写成 11 月。说明里出现过的句子，不等于你这台设备今天已经能点开。排期以 11 月、且没有具体日期为准。

Freeform 在同一篇新闻稿里有文字样式、白板背景色，以及 12 月才能把图片交到 Pixelmator Pro 里编辑、用文字描述生成可编辑形状。heise 指出，苹果没有说明 Freeform 是否支持 MCP。白板要不要接代理，目前没有公开答案，清单里先空着。

## 为什么要单独看「外部代理能改办公文件」

以前把材料交给模型，常见做法是复制一段到聊天窗口，或者导出文件再上传。你没贴出去的页，模型看不到；改完的文字，也要你自己贴回去。内置助手是另一条路：它待在 Keynote、Pages、Numbers 里面。按苹果的说法，它理解当前文档的上下文，人不用先离开文稿。

MCP 是第三条路，而且和助手不是同一个开关。MCP 是 Anthropic 提出的开放标准，用来把 AI 模型和应用、数据连起来。iThinkDiff 的区分可以直接用：三款应用里的助手跑在苹果自家模型和 OpenAI 上；MCP 是给外部代理和工具的门。门打开之后，你已经在用的代理可以读这三款应用里的内容、改内容、在应用里面做自动化。

这件事对用 AI 干活的人有两层具体含义。

第一，这周的流程不用为了新闻稿停下来。助手还是 beta，语言只有美式英语，系统要到 27，上架日也没定。中文材料、Windows 同事、这周要交的周报，继续走已经跑通的工具。写作仍按 [AI 写作工具横向对比](/posts/ai-writing-tools-comparison/) 里的办法选；表格里的求和、占比仍按 [AI 数据整理工具怎么选](/posts/ai-spreadsheet-data-cleaning/) 的规则，用表格公式计算，模型给出的数要能回到原始单元格。

第二，值得现在做的是分拣，不是迁移。等 11 月的版本出现在一台测试 Mac 上，你要能马上回答：哪一份周报可以让代理改副本，哪一份客户表连读都不能读。哪些步骤必须人确认，和 [主动型代理该交给它哪些活](/posts/claude-duet-proactive-agent-guide/) 是同一类决定。那篇文章讲的是另一个产品，权限问题是同一类：代理可以起草和整理，对外发送、付款和改原件仍留在人手里。

## 和你已经在用的工具怎么并存

按「谁在读文档、改动落在哪里」分成三档，三档可以同时留着。

**你现在的通用模型。** 你复制文字，或上传导出的文件。文档留在原来的应用里。语言和供应商你自己选，中文材料今天就能做。上下文靠你粘贴，改完的段落也要你贴回去。

**三件套里的 beta 助手。** 苹果写明它基于自家模型和 OpenAI，理解当前文档。能力范围就是上一节那张表。它要求支持 Apple Intelligence 的设备，系统是 iOS 27、iPadOS 27 或 macOS 27 及以上，目前仅美式英语。heise 写明，苹果没有说测试何时结束，也没有说德语何时支持。中文何时支持，这些来源里都没有。

**外部代理经 MCP 进入应用。** 新闻稿写明外部 AI 代理和工具能做三件事：读内容、执行编辑、在应用内执行自动化。iThinkDiff 把它理解成你已经在用的代理和工具的入口。新闻稿没有列出兼容名单，某一种代理能不能接上，要等开关出现后再看。入口只在 Mac，而且要 macOS 27 或更高。heise 把 MCP 理解成只要求 macOS 27、仅限 Mac，没有像助手那样再加一条 Apple Intelligence。某一台英特尔 Mac 能不能装上 macOS 27，这些来源没有写，以苹果对那台机器的系统升级说明为准。

新闻稿把 Logic Pro 浏览器里的音乐理解写成在设备上分析音频。Keynote、Pages、Numbers 的助手没有同样的「在设备上」这句话。助手被写成基于苹果模型和 OpenAI，至于哪一类请求由哪一个模型处理、内容何时离开设备，heise 指出苹果没有解释。在权限界面被你自己看到之前，把助手和 MCP 都当成「内容有可能离开这台 Mac」。

同一周不要把三档同时接到同一份对外文件上。中文周报留在第一档。一台测试 Mac 升到 27 之后，用一份不含客户数据的英文提纲试第二档或第三档。改错了，你才知道是哪一档改的。

## 苹果还没说明的权限问题

heise 把缺口写得很具体。下面每一条都是新闻稿没有回答的问题。

- 访问要不要按文档、按代理或按会话单独授权。
- 修改要不要人确认。
- 怎样防止误改，怎样防止文档内容外泄。
- 哪一个模型处理哪一类请求。
- 内容什么时候离开设备。
- Freeform 是否支持 MCP。
- MCP，以及 Pixelmator Pro 的 Generate Fill，是否提供美式英语以外的语言。助手本身「仅美式英语」是新闻稿脚注写明的；MCP 的语言范围，heise 认为还不清楚。

Numbers 还有一个单独的核对问题。助手被写成可以计算，也可以用世界知识生成自定义表格。新闻稿没有写这些数字和「世界知识」如何与你的源数据对照。对外汇报、报价、工资和合同里的数，仍以表格里能追溯的单元格为准。9to5Mac 引用的说明里还有「检索较新的信息并写进文档」。如果 11 月的版本带这项，它和「内容何时离开设备」是同一个还没回答的问题：检索外部信息，至少有一次请求要离开文稿所在的环境。含未公开数字的文稿，先不要用来试这项。

在上述句子被苹果补上之前，操作规则收成一句：代理只打开副本，对外版本由人保存。

## 更新落地前可以先做的核对

### 系统和订阅分开记

先写四行：这台设备支不支持 Apple Intelligence；现在的系统版本；文稿主要是中文还是英文；团队是否已经订阅 Apple Creator Studio。

助手要前两行同时满足，并且目前只处理美式英语。MCP 的脚注只要求 Mac 上的 macOS 27 或更高。应用本身按脚注可以留在 macOS 26、iOS 26 或 iPadOS 26。升到 27 是为了助手和 MCP，不是为了继续打开现有文稿。团队里没有必须这周就试的英文材料，就不要为了一个还没有上架日期的 beta，给所有 Mac 升级。留一台允许试新系统的 Mac 即可。

订阅按「是不是已经在付」分开。已经订阅的人，11 月的更新免费，具体哪一天没有公布，App Store 出现之后再更新那台测试机。还没订阅的人，美国区新闻稿写的新用户价格是每月 12.99 美元或每年 129 美元，新订阅有一个月免费试用。教育优惠是每月 2.99 美元或每年 29.99 美元，对象是新订阅的大学生和教师，需要验证，并且不覆盖家庭共享组，新闻稿把它写成可能随时结束的限时优惠。heise 写德国价格为每月 13 欧元或每年 129 欧元。中国区售价，这五篇来源都没有，以下单页面为准。

免费版的 Keynote、Pages、Numbers、Freeform，新闻稿写明会继续提供，并随每一台新的 iPhone、Mac 和 iPad 附带。9to5Mac 写道，智能助手面向 Creator Studio 订阅者，新的交换格式则是所有用户都能用。iThinkDiff 写：在 App Store 里创建和编辑 Keynote 演示文稿不需要订阅，智能功能需要。MCP 能不能在不订阅时使用，heise 写明苹果没有说，并认为高级内容和内置 AI 功能很可能仍是订阅专属。在苹果写清楚之前，两头都不要先假定：不要假定不订阅也能接上外部代理，也不要为了还没看到的 MCP 开关先付一年。

新闻稿还写，最多六名家庭成员可以通过家庭共享使用 Creator Studio 里的应用和内容。这一段没有另外给出按公司席位计费的价格。小团队如果不是同一个家庭共享组，不要把「六人」当成公司许可。

### 先把流程分成三堆

从上周真实做过的文件里抽，不从新闻稿的演示里抽。每份只标三行：输入是什么，做完算什么，错了谁来改。

**可以等测试机出现后再试的。** 不含客户和个人信息、弄坏了可以重做、最好是英文的内部提纲；版式还没定的练习用幻灯片；图表类型还没选定、数字已经由公式算完的练习表。试的范围按新闻稿已经写明的能力来：Keynote 试设计和动画，Pages 试一段英文草稿的重组，Numbers 试图表类型建议。世界知识生成的新表，只放在练习文件里，不放进要发出去的月报。

**继续用现有工具、不交给这次更新的。** 中文客户方案、工资表、未发布的经营数字、合同，以及任何会自动发出去的邮件或链接。合同和财务申报这一类，核对成本往往吃掉起草省下的时间，衡量方法见 [AI 提效到底省了多少时间](/posts/ai-productivity-measurement/)。省下的起草分钟要和返工分钟放在一起看。

**先空着的。** Freeform 白板。是否支持 MCP 没有说明，就不要写进代理清单。

销售周会的演示文稿可以拆开：版式和动画属于第一堆，报价页属于第二堆。市场月报同样拆开：英文内部摘要可以等助手试起草，中文对外稿继续由人定稿。运营周数据里，图表类型可以试建议，汇总数留在公式里。

### 权限界面出现之前，用副本代替授权

苹果没说会不会按文档、代理或会话征求同意，也没说改动要不要确认。测试机上的做法先写死：

1. 复制一份文件再打开，文件名带日期。原件不放到代理能写入的位置。
2. 代理或助手只打开这份副本。
3. 改完由人对比副本和原件，再决定要不要把改动拷回去。
4. 对比时专门找两样东西：你没要求它改的数字，以及用「世界知识」新长出来的表格。出现任意一样，这份副本作废，计算交回表格公式。

界面上如果以后出现授权和确认的说明，把原文抄下来，对照上面 heise 列的缺口。抄下来之前，规则不变。

### 中文用户和 Windows 团队各自留一条能交差的路

内置助手目前仅美式英语。中文、德语或其他语言的时间表没有公布。中文材料继续用你已经在用的模型，处理导出的文字或表格。11 月的版本如果在测试机上只能处理英文，就只拿英文提纲做试验，中文终稿仍由人完成。

MCP 的语言范围是未知数，不要把它提前说成「外部代理就能处理中文文稿」。即使你的代理本身会中文，苹果应用这一层是否只开放美式英语，heise 认为尚不清楚。等测试机上能打开 MCP，再用一份无关紧要的中文副本试一次读和一次改。试通之前，中文交付流程保持原样。

Windows 同事不进这条路径。MCP 仅限 Mac，要求 macOS 27 或更高，新闻稿没有 Windows 版。Windows 上的汇报、表格和方案继续用现有工具。团队里如果有一台用来试的 Mac，指定一个人负责副本。公司共享位置上的唯一原件，不要交给那台机器上的代理。混合团队写成一句就够：原件在谁手里，谁保存；代理只改带日期的副本。

## 测试机上真的出现更新之后

11 月的更新出现在 App Store，并且你决定只升一台 Mac 时，先做三件再考虑第二台。

用一份不含敏感信息的英文 Keynote 副本。助手如果出现，只让它改版式或动画，不改已经核对过的数字页。MCP 的开关如果出现，先读界面上关于授权、确认和数据去向的原文。界面上仍然没有这些句子，就继续只开副本。

再看同一份演示文稿能不能以 .keyx 导出或另存，以应用里实际出现的菜单为准。苹果说这个 JSON 包是给外部工具和代理读的。能导出，只说明文件更好读，不说明代理已经有权改你的 iCloud 原件。Pages 和 Numbers 没有对应格式，这两类文件不要交给一个离线脚本去猜内部结构。

最后记三行：改动是否被你采纳、返工多少分钟、有没有出现你没要求的数字或新表格。三行都干净，再考虑第二份文件。有一行是未要求的数字，就停在这一份。

## 常见问题

### 现在就要把 Mac 升到 macOS 27 吗？

### 不订阅 Apple Creator Studio 能不能用助手和 MCP？
