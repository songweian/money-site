每个团队里大概都有一张这样的表：几千行客户记录，公司名有的带括号有的不带，日期混着「2026/3/5」和「2026年3月5日」，同一家公司被写成三种简称，还有一列备注里塞了地址、电话和内部吐槽。

这类活儿最耗人，也最适合交给模型。但很多人试过一次就放弃了——不是模型不会做，而是做法不对：整份表丢进去，等半天，拿回来一份看起来很整齐、但行数少了一截的结果。

## 为什么表格数据最容易见效，也最容易翻车

表格数据有三个特点，决定了它和「写文章」是完全不同的任务。

第一，规则通常是明确的。什么叫同一个客户、什么算有效手机号、日期该长什么样，你心里其实有标准，只是没法用公式写出来。而明确规则恰恰是模型最擅长的执行对象。

第二，错误是隐蔽的。文章写错了你能一眼看出来，表格错了一行你可能三个月后才发现。模型漏掉三十行记录，输出照样整整齐齐。

第三，校验成本可控。正因为规则明确，你完全可以用「行数对不对」「汇总值对不对」「空值有多少」这几个机械指标，在几秒钟内判断结果能不能用。这比校验一篇文章容易得多。

所以核心结论是：**让模型做它擅长的部分（理解语义、统一格式、归类判断），把算术和校验留给表格函数和脚本。** 这一点想清楚，后面所有流程都顺了。

## 先分清三条处理路径：直接对话、表格插件、脚本加 API

选工具之前，先选路径。同样一句「帮我把这列公司名统一」，走不同路径的成本和风险差别很大。

| 维度 | 直接对话（复制粘贴） | 表格插件 / 内置 AI | 脚本 + API 批处理 |
|---|---|---|---|
| 适用数据量 | 几十行以内 | 单次数百到数千行 | 上万行，且需重复执行 |
| 上手成本 | 最低，会复制粘贴就行 | 低，装插件或开通功能 | 需要基础脚本能力 |
| 结果可复现 | 差，同一份数据每次可能不同 | 中等，取决于参数是否固定 | 好，脚本与提示词固化后稳定 |
| 结构化输出 | 靠提示词约束，容易串行 | 通常直接写回单元格 | 可强制校验字段名与类型 |
| 计算准确性 | 不可靠，不要让它算数 | 建议仍用表格函数算 | 由脚本计算，模型不碰数字 |
| 数据出网范围 | 取决于所用产品的政策 | 取决于所用产品的政策 | 可控，能留在内网环境 |
| 典型任务 | 一次性清洗、统一命名 | 日常补列、生成公式 | 每周固定整理、多表合并 |

判断方法很简单：**看这个任务会不会重复发生。** 只做一次的直接对话就够了；每周都要做一次的，哪怕多花两小时搭脚本也值得，因为第三次就能回本。

## 动手之前：先把表格收拾成模型能读懂的样子

大部分失败案例，问题出在投喂的原始数据上。

**收敛列，不要整表丢。** 整理公司名只需要「客户名称」这一列，就只给这一列。多给十列无关字段，只会稀释注意力并增加出错面积。

**加一列行号。** 这是最容易被忽略、也最有用的一步。给每行编一个原始行号并在输出中保留，你就能把结果和原表精确对齐，漏行、串行一眼可见。

**处理合并单元格与空行。** 合并单元格在导出为文本时经常变成只有首行有值、其余为空，模型会把空值当成缺失数据自行猜测。动手前先取消合并并向下填充。

**把「备注」这类自由文本单独拎出来。** 混合了多种信息的自由文本，适合用「提取」而不是「清洗」的方式处理：明确告诉模型要从中抽出哪几个字段，抽不出来的标为待定，而不是让它改写。

## 四步实操流程：清洗、归类、提取、校验

### 第一步：清洗——只做确定性改写

清洗的目标是让格式统一，不涉及任何判断。典型任务是：日期统一成 `YYYY-MM-DD`、去掉首尾空格与不可见字符、全角转半角、手机号去掉分隔符、公司名去掉后缀括号内容。

提示词里要写明「只做格式变换，不修改任何实际内容，不增删行」。清洗完成后，用一句话就能验证：除目标列外，其余列应与原表逐字一致。

### 第二步：归类——把判定标准写成枚举

归类是模型价值最高的环节，也是最容易翻车的环节。关键在于**不要让模型自由发挥类别名称**。

做法是先扫一遍数据，自己定好类别清单，例如「制造业 / 贸易零售 / 服务业 / 教育培训 / 其他」五类，并在提示词里给出每类的典型例子各两三个。同时明确写「只能从这五类中选一个，不确定时选『其他』并在备注列说明原因」。

这一步的产出必须包含「置信度」或「判定依据」列，便于人工只复核低置信度的行，而不是从头看一遍。

### 第三步：提取——从自由文本里抽字段

面对「备注」这类列，明确列出要抽的字段名与类型，要求输出为表格，抽不到的留空而不是编。

例如从客户备注里抽「对接人、所属行业、是否需要发票、历史合作年份」四个字段，就明确写：每项若原文未提及则输出空值，禁止根据公司名推测。

### 第四步：校验——三个必须跑的机械检查

结果拿回来之后，不论看起来多整齐，都要跑这三个检查：

1. **行数核对**：输出行数是否等于输入行数。少一行就说明有漏，多一行就说明有拆。
2. **汇总核对**：对某一数值列分别用原表和结果表求和，两者必须相等。这一步能抓住绝大多数串行与丢失。
3. **空值与枚举核对**：新增的归类列里，空值数量是多少、是否出现了清单外的类别值。出现清单外的值，说明提示词约束没生效，需要重跑而不是手动改。

这三项都可以通过表格公式在几十秒内完成，不需要写脚本。

## 三个高频坑：数字幻觉、行数上限、格式污染

**数字幻觉。** 模型会一本正经地算出一个看起来合理的汇总值，而这个值没有任何计算依据。规避原则是：所有需要精确计算的环节一律交给表格函数或脚本，模型只负责口径说明和文字描述。如果一定需要模型输出数字，就要求它附上「该数字来自原始表格第几行第几列」，没有来源的输出直接判废。

**行数上限。** 单次对话能稳定处理的数据量有限，具体上限取决于所用产品与套餐，且会随版本变化，请以官方说明为准。稳妥做法是不去试探上限，而是主动分批：每批控制在几百行以内，批次之间保持同一份提示词，最后合并结果再做一次行数和汇总核对。

**格式污染。** 模型输出里混入解释文字、序号被改成 `1.` 而不是原行号、数字被加上千分位逗号、日期被自动转成本地化格式——这些都会让结果无法直接贴回表格。解决办法是在提示词里明确输出契约：只要一个 Markdown 表格或 CSV，不要任何前后说明文字，数值保持原始字符串，日期严格使用指定格式。

## 哪些表不该交给在线模型

判断标准只有一条：**这份数据泄露出去，会不会造成实际损失。**

含个人身份信息（手机号、身份证号、住址、银行账号）、未公开的财务数据、客户合同价格、员工薪酬、内部人事评价的表格，在使用任何在线服务之前，都要先确认两件事：一是公司的数据使用政策允许什么，二是该服务当前对输入内容的处理方式（是否用于训练、保留多久、是否人工抽检）。这两项都会随时间变化，请以官方最新说明为准，不要依据几个月前的文章下判断。

存疑时的默认动作是脱敏：只保留整理任务必需的字段，把标识性内容替换成编号，处理完再映射回去。为了省这一步而承担数据风险，通常不值得。

## 一套可以复用的提示词骨架

把下面这份骨架存成模板，每次只改方括号里的部分，比每次临时写提示词稳定得多：

```
你是一个严格的数据整理工具，只做格式与分类处理，不做任何推断。

【任务】对下方表格的 [列名] 列执行 [清洗/归类/提取]。
【规则】
1. 只输出一个 Markdown 表格，包含原始行号列，不要任何解释文字。
2. 行数必须与输入完全一致，不得增删、合并或拆分行。
3. 归类只能从以下枚举中选择：[类别A / 类别B / 其他]。
4. 原文未提及的字段输出空值，禁止推测、禁止补充常识。
5. 数值保持原始字符串，不要添加千分位或单位。
6. 判定不确定时选择「其他」，并在 [置信度列] 标注 low 并简述原因。

【示例】
输入：[……]  输出：[……]
输入：[……]  输出：[……]

【数据】
[粘贴数据]
```

第六条的置信度标注是最容易被省掉、也最有用的一行。它把「人工从头复核一遍」变成了「人工只看标注 low 的行」，复核时间通常能压到原来的十分之一。

## 常见问题

### 几千行的 Excel 可以直接整份丢给模型整理吗？

不建议整份丢。行数过多时模型容易只看到片段、漏掉后面的记录，输出还可能串行。正确做法是按批次拆分，每批控制在模型能稳定处理的范围内，要求它只输出结构化结果，最后用脚本或公式核对总行数与汇总值是否与原表一致。

### AI 整理出来的数字能直接对外汇报吗？

不能。模型擅长格式统一、分类和文本归纳，不擅长精确算术。涉及求和、占比、同比这类需要精确计算的内容，一律让表格函数或脚本计算，模型只负责口径说明和文字描述。任何对外汇报的数字都要能追溯回原始单元格。

### 表格里含客户手机号和身份证号，能用在线 AI 整理吗？

先看公司的数据使用政策，再看所用产品当前对输入内容的处理方式，这两项都会变化，请以官方最新说明为准。存疑时的稳妥做法是先在本地做脱敏，只保留整理任务必需的字段，或者改用能部署在内网的环境处理。

### 为什么同一份表格让 AI 整理两次，结果不一样？

因为模型输出带有随机性，加上提示词里没有写死判定规则。解决办法是把分类标准写成枚举清单并举例，把温度类参数调低，把输出格式固定成表格或 JSON；判定规则越明确，两次输出的差异越小。
